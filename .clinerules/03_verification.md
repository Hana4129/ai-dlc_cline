# 03_verification.md — 検証フェーズのルール

## 目的

実装が「計画の完了基準」を満たしているかを客観的に確認する。

---

## 検証の手順

1. **ビルド確認**：コンパイル・構文チェックを実行する
2. **テスト実行**：既存テストがすべてパスすることを確認する
3. **新規テスト**：新しい機能・バグ修正には対応するテストを追加する（プロジェクトルールで上書き可）
4. **完了基準の照合**：計画フェーズで定めた完了基準を1つずつ確認する

---

## ビルド・テストコマンド

プロジェクト固有のコマンドは `99_local.md` で定義する。
定義がない場合は以下のフォールバックを試みる：

```
# JavaScript/TypeScript
npm run build && npm test

# Python
python -m pytest

# Go
go build ./... && go test ./...

# Rust
cargo build && cargo test
```

---

## テスト結果の判定

**成功：**
- ビルドがエラーなく完了
- 既存テストが全パス
- 新規テストが全パス

**失敗時の対応：**
1. エラーメッセージを読み、原因を特定する
2. 実装フェーズに戻って修正する（ループ内リトライ）
3. 同じエラーが2回続いた場合はアプローチを変える
4. 3回続いた場合はエスカレーション（00_meta.md参照）

---

## 手動確認が必要なケース

以下は自動検証できないため、ユーザーに確認を依頼する：

- UIの見た目・操作感
- パフォーマンス要件
- 外部サービスとの連携
- セキュリティ要件の充足

---

## 検証フェーズの完了基準

- ビルドが成功している
- 既存テストが全パスしている
- 計画の完了基準を全項目確認している
